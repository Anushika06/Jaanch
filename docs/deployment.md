# Deployment guide (free tier)

This guide deploys Jaanch on free plans:

| Piece                                       | Provider                                        | Why                                                                               |
| ------------------------------------------- | ----------------------------------------------- | --------------------------------------------------------------------------------- |
| API + WhatsApp webhook + worker (+ web app) | **Render** free web service (Docker, Singapore) | Long-running process for the worker; HTTPS URL for Twilio                         |
| Database                                    | **Neon** free Postgres (Singapore)              | Does not expire (Render's free Postgres is deleted after 30 days); scales to zero |
| Web app (optional, recommended)             | **Vercel** Hobby                                | Always fast even while the Render service is asleep                               |
| Daily data refresh (optional)               | **GitHub Actions**                              | Free scheduled jobs; the server also refreshes on boot                            |
| WhatsApp                                    | **Twilio** WhatsApp Sandbox                     | Testing channel anyone can join                                                   |
| AI reading                                  | **NVIDIA** API catalog (build.nvidia.com)       | Vision + text models, Hindi speech-to-text                                        |

> **Before real users:** the NVIDIA API catalog's trial terms do not allow production use or
> personal data, and the Twilio sandbox is a shared test number. Both are fine for the prototype
> and the demo. See [trust-and-safety.md](trust-and-safety.md).

## 1. Accounts you need

1. **GitHub** — to host the repository (Render and Vercel deploy from it).
2. **Neon** — https://neon.tech (sign up with GitHub).
3. **Render** — https://render.com (sign up with GitHub).
4. **Vercel** — https://vercel.com (optional; Hobby plan is for non-commercial use).
5. **Twilio** — https://www.twilio.com/try-twilio.
6. **NVIDIA** — https://build.nvidia.com (API key).

## 3. Database (Neon)

1. Create a project: region **AWS Asia Pacific (Singapore)**, Postgres 17.
2. Copy the **direct** connection string (the worker holds a normal connection; the `-pooler`
   endpoint is for serverless functions). Ensure it ends with `?sslmode=require`.
3. Optional: in _Compute_, fix the size at the minimum (0.25 CU) so it never auto-scales up.
4. Nothing else: tables are created automatically on first start (migrations run at boot).

**Storage:** none to configure. Uploaded media lives in Postgres for minutes and is deleted after
reading.

## 4. Backend on Render

1. Push the repository to GitHub (Render deploys from a repository you own).
2. Render dashboard → **New → Blueprint** → select the repository. Render reads
   [`render.yaml`](../render.yaml): one free Docker web service in Singapore with a health check
   on `/healthz`.
3. Fill the variables marked `sync: false`: `PUBLIC_BASE_URL` (you can fill it after the first
   deploy shows the URL), `DATABASE_URL`, `NVIDIA_API_KEY`, `TWILIO_ACCOUNT_SID`,
   `TWILIO_AUTH_TOKEN`, `TWILIO_SANDBOX_JOIN_CODE`, and `WEB_BASE_URL` if using Vercel.
4. Deploy. The first boot runs migrations and, because no snapshot exists, ingests SEBI's
   registers and the RBI Alert List in the background (about a minute). Watch the logs for
   `ingestion finished`.
5. Verify:
   - `https://<service>.onrender.com/healthz` → `{"ok":true,...}`
   - `https://<service>.onrender.com/api/v1/sources` → SEBI categories with today's/yesterday's date
   - Logs show `language model available` for each configured model (a `not available` warning
     means a model was retired: set `LLM_VISION_MODEL`/`LLM_TEXT_MODEL` to models reported live by
     `pnpm --filter @jaanch/llm probe`).

**Free-plan behaviour.** The service sleeps after 15 minutes without traffic and takes about a
minute to wake. A WhatsApp message that arrives while it sleeps is not lost: on boot, Jaanch asks
Twilio for recent inbound messages and processes any it missed. For a demo, open `/healthz` a few
minutes beforehand. (Keeping a free service awake with an external pinger is a grey area under
Render's terms; the paid Starter plan removes sleeping.)

## 5. Web app

**Option A — served by Render (simplest).** Nothing to do: the Docker image includes the built
web app at the service URL. Downside: the first visit after idle waits for the cold start.

**Option B — Vercel (recommended for demos).**

1. Vercel → **Add New → Project** → import the repository, set **Root Directory** to `apps/web`.
2. In [`apps/web/vercel.json`](../apps/web/vercel.json), replace
   `REPLACE-WITH-YOUR-RENDER-SERVICE` with your Render service name, commit and push. API calls
   are proxied to Render, so the browser sees one origin (no CORS setup).
3. Deploy, then set `WEB_BASE_URL=https://<your-project>.vercel.app` on Render so WhatsApp report
   links open the Vercel site.

## 6. WhatsApp: Twilio Sandbox and webhook

1. Create a Twilio account and verify your phone number.
2. Open the WhatsApp Sandbox: Console → **Messaging → Try it out → Send a WhatsApp message**
   (legacy console: `https://console.twilio.com/us1/develop/sms/try-it-out/whatsapp-learn`).
   Accept the terms. Note the sandbox number (+1 415 523 8886) and your join phrase.
   - If your trial account only shows "Try out WhatsApp" with fixed templates and no sandbox
     settings, the sandbox requires an upgraded account (Console → Admin → Upgrade). Jaanch needs
     free-form replies, which the template-only flow does not allow.
3. From your phone, send the join phrase to the sandbox number.
4. **Sandbox settings → Sandbox configuration**:
   - _When a message comes in_: `https://<service>.onrender.com/webhooks/twilio/whatsapp`, method **POST**
   - _Status callback URL_: `https://<service>.onrender.com/webhooks/twilio/status`
   - Save.
5. Make sure `PUBLIC_BASE_URL` on Render is exactly `https://<service>.onrender.com` — Twilio's
   signature is computed over the URL it calls; a mismatch returns 403.
6. Test: send `HELP` → you get the welcome. Forward a message → "Checking…" then the report.

Sandbox limits: 1 message per 3 seconds (Jaanch paces automatically), 50 messages/day on a trial,
and each person must re-send the join phrase every 3 days.

**Moving to a production WhatsApp sender later:** register a WhatsApp sender in Twilio (requires
Meta business verification), set `TWILIO_WHATSAPP_FROM` to it (or `TWILIO_MESSAGING_SERVICE_SID`),
and point that sender's webhook at the same URLs. No code changes.

## 7. Domain (optional)

Add a custom domain in Render (API) and/or Vercel (web), then update `PUBLIC_BASE_URL`,
`WEB_BASE_URL`, the Twilio webhook URLs and `apps/web/vercel.json`.

## 8. Production security checklist

- [ ] `NODE_ENV=production` (the server refuses to start without `APP_SECRET`, with fixture data
      or with signature checks disabled).
- [ ] `APP_SECRET` is random and only in Render's environment.
- [ ] `TWILIO_VALIDATE_SIGNATURE=true` (default).
- [ ] `ADMIN_TOKEN` set only if you use `/admin/*`; keep it secret.
- [ ] `CORS_ORIGINS` empty unless a browser app on another origin calls the API directly.
- [ ] No `.env` committed (`git status` must not list it).

## 9. Daily data refresh (optional)

The server refreshes snapshots older than 24 hours whenever it boots. For a guaranteed daily
refresh while the service sleeps, enable [`.github/workflows/ingest.yml`](../.github/workflows/ingest.yml):
GitHub → repository → **Settings → Secrets and variables → Actions** → add `DATABASE_URL`. It runs
daily at 02:37 IST and can be started by hand (Actions → Refresh official data → Run workflow).
Alternatively call `POST /admin/ingest` with `Authorization: Bearer <ADMIN_TOKEN>` from any
scheduler.

## 10. Smoke test after every deploy

```bash
API=https://<service>.onrender.com
curl -s $API/healthz
curl -s $API/readyz
curl -s $API/api/v1/sources | head -c 400
curl -s -X POST $API/api/v1/investigations -H 'content-type: application/json' \
  -d '{"text":"SEBI Registered RA, Reg No INH000011431. Guaranteed 30% monthly returns. Pay to 9876501234@ybl","locale":"en"}'
# then GET $API/api/v1/investigations/<id> until "status":"completed"
```

Then on WhatsApp: `HELP`, a forwarded message, `PAID`, `HINDI`, `DELETE`.

## 11. Rollback and troubleshooting

| Symptom                        | Check                                                                                           | Fix                                                                                      |
| ------------------------------ | ----------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| Deploy fails health check      | Render logs: configuration errors are printed at start-up                                       | Set the missing variable                                                                 |
| WhatsApp: no reply at all      | Twilio Console → Monitor → Logs → Errors (11200 = webhook unreachable/timeout; 403 = signature) | Wake the service; make `PUBLIC_BASE_URL` match the webhook URL exactly                   |
| WhatsApp: error 63015          | The phone's sandbox session expired                                                             | Re-send the join phrase                                                                  |
| WhatsApp: error 63038          | Trial daily limit (50) reached                                                                  | Wait or upgrade                                                                          |
| Screenshots "couldn't be read" | Logs: `language model … not available`                                                          | Run the probe, set live model IDs                                                        |
| Old "as of" dates in reports   | `/api/v1/sources`                                                                               | `POST /admin/ingest` or restart the service                                              |
| Database suspended             | Neon dashboard: compute quota                                                                   | Wait for the monthly reset or reduce traffic; the worker makes no idle queries           |
| Bad release                    | Render → Deploys                                                                                | **Rollback** to the previous deploy (migrations are additive; no down-migrations needed) |

## Local development with a public webhook

```bash
pnpm install
cp .env.example .env              # add NVIDIA_API_KEY, Twilio values
pnpm --filter @jaanch/web build   # so report links on the tunnel URL open the web app
pnpm dev                          # API on :8787, web dev server on :5173 (proxying /api)
pnpm tunnel                       # cloudflared quick tunnel → https://<random>.trycloudflare.com
```

Set `PUBLIC_BASE_URL` in `.env` to the tunnel URL, restart `pnpm dev`, and paste
`https://<random>.trycloudflare.com/webhooks/twilio/whatsapp` into the sandbox settings. Quick
tunnel URLs change on every run.
